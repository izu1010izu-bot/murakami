# SNS投稿下書き作成(Instagram / damage_mark_official)

村上さんの「文章を考える手間」を減らしつつ、**AIが書いたと分からない、村上さん本人の言葉づかいの投稿文**を作ることが最重要目的。下書きの自動投稿はまだ行わない(第1段階は下書き作成まで。投稿は村上さんが自分でInstagramアプリから行う)。

**承認プロンプトを減らすため、Google Drive操作の回数は最小限にする**(村上さんの指定)。管理用スプレッドシートは廃止し、下書きファイル1本に情報を集約する。

## 使用するGoogle Driveフォルダ

- 素材: 「SNS用画像」フォルダ(https://drive.google.com/drive/folders/1nqCGmTC88rQRlhrWUVJ4w7A_kRbbDAva)
- 下書き: 「SNS運用管理/下書き」フォルダ(https://drive.google.com/drive/folders/1Aqyicr-S-Qfco5QWFR4y0MjhHVkUyfhj)
- 文体ガイド: 「SNS運用管理/文体サンプル」フォルダ(https://drive.google.com/drive/folders/1bC1L8WRyg6s0nf7WcLqsVBjRzInrOBpt)← `style_guide.md` をここに保存

※ 以前あった「素材管理」「投稿履歴」スプレッドシートは廃止済み(Google Sheetsは行の部分更新APIがなく、更新のたびに trash→再作成が必要で承認回数が増えるため)。使用素材・作成日・キャプション案は下書きファイル自体に書く。

ファイルの検索・作成・読み書きにはGoogle Drive連携ツール(search_files / create_file / read_file_content / download_file_content 等)を使う。

## 全体の処理フロー

### ステップ0: 文体ガイドの確認・ヒアリング(初回のみ、以後はスキップ)

1. 「文体サンプル」フォルダに `style_guide.md` があるか確認する。
2. なければ、村上さんに以下の観点を質問形式でヒアリングし、回答をもとに `style_guide.md` を作成して「文体サンプル」フォルダに保存する。一度に全部聞く必要はなく、2〜3個ずつ聞いてよい。
   - 普段の一人称(私/僕/自分の名前 等)
   - 文末の口調(です・ます調か、だ・である調か、カジュアルな口語か)
   - よく使う言い回し・口癖・絵文字の使い方(頻度・好んで使う絵文字)
   - 逆に「絶対に使わない」表現・NGワード(硬すぎる敬語、紋切り型のフレーズ等)
   - 投稿の長さの目安(短文中心か、しっかり語るタイプか)
   - ブランド・アカウントとしての世界観やコンセプト(damage_mark_officialとしてどんな雰囲気を出したいか)
   - ハッシュタグの使い方(付ける/付けない、よく使うタグ)
3. `style_guide.md` は箇条書きでよい。完璧を目指さず、まずは骨子を作る。実際に下書きを作ってみて村上さんから「AIっぽい」「違う」というフィードバックがあれば、都度このファイルを更新して精度を上げていく。

### ステップ1: 素材の準備(2つの起動パターン)

**パターンA: チャットに画像が添付されている場合(メイン導線)**
1. 添付された画像を、そのまま `create_file` で「SNS用画像」フォルダに保存する(区別用のサブフォルダは作らない)。
2. その画像の内容(写っているもの・シーン)を直接見て把握する(Driveへの読み込みは不要、チャットで受け取った画像をそのまま見ればよい)。

**パターンB: 画像添付なしで「SNS投稿案を作って」等と声がかかった場合(フォールバック)**
1. 「SNS用画像」フォルダを `search_files` で一覧取得する。
2. その場でランダムに1点選ぶ(過去の使用回数などは記録していないため、単純な乱択でよい。同じ写真が続けて選ばれても許容する)。
3. 選んだ画像ファイルをダウンロードして内容を確認する(download_file_content → base64デコードして画像として読み込む)。

### ステップ2: キャプション案の作成

1. `style_guide.md` の内容を必ず踏まえて、素材の内容に合ったキャプション案を1〜3パターン作成する。
2. 次のような紋切り型のAIっぽい表現は避ける: 「〜してみました!」「ぜひチェックしてみてください」「いかがでしたでしょうか」「〇〇な一日でした」等の定型オチ、機械的な絵文字の羅列、説明的すぎる文章。
3. **文章の構成そのものも毎回変える**(村上さんの指定)。「事実描写→感想」のような同じ型を毎回繰り返さず、書き出し方・展開・締め方・文の長さを投稿ごとに変化させる。複数案を作る際も、言い換えバリエーションではなく構成が異なる案を混ぜる。
4. `style_guide.md` にNGワードの指定があれば厳守する。
5. ハッシュタグは `style_guide.md` の方針に従う(方針が未定なら付けずに提案するだけにする)。

### ステップ3: 下書きの保存(create_file 1回のみ)

「下書き」フォルダに `年-月-日-下書き.md`(当日の日付、同日に複数回作成する場合は末尾に連番)として、以下をまとめて保存する:
- 作成日
- 使用素材(パターンAならファイル名、パターンBなら選んだファイル名)
- キャプション案(1〜3パターン)

これで完結させ、別途スプレッドシートには記録しない。

### ステップ4: 村上さんへの報告

作成したキャプション案と、使った素材、下書きファイルの保存先を簡潔に伝える。投稿は村上さんが内容を確認し、良ければ自分でInstagramアプリにコピーして投稿する(この段階では自動投稿は行わない)。

**下書きファイル自体には「確認事項」「リクエスト」等の文章を含めない**(村上さんの指定)。商品名やハッシュタグが不明な場合も、確認を求める一文を下書きに書かず、分かる範囲でキャプション案だけを作成する。判断が必要な点があれば、報告時の会話で簡潔に触れる程度にとどめる。

## 運用ルール

- 起動は村上さんの声かけ、またはチャットへの画像添付による都度実行のみ。自動の定期実行は行わない。
- 投稿頻度は週1回想定、下書きは2日に1回程度のペースで声がかかる想定(下書きを複数ストックし、村上さんが選ぶ)。
- 1回の下書き作成で発生するGoogle Drive操作は、パターンAなら2回(画像保存+下書き保存)、パターンBなら3回程度(素材一覧取得+ダウンロード+下書き保存)に収まるようにする。承認プロンプトの回数を増やす追加の書き込み(スプレッドシート等)は行わない。
- 生成した文章が「AIっぽい」と村上さんからフィードバックがあった場合は、`style_guide.md` を一緒に更新し、次回以降の精度を上げていく。
- 自動投稿(Instagram Graph API連携)は将来の拡張候補だが、Meta側のビジネスアカウント化・アプリ審査等が必要なため今回のスキルには含めない。Instagramアプリの「下書き」機能への直接書き込みは公開APIが提供されておらず不可。
- Google Drive関連ツールの承認プロンプト自体を減らしたい場合は、村上さんご自身が `.claude/settings.json` の `permissions.allow` に該当ツール名を追加するか、承認時に「今後も許可」等の選択肢を選ぶ必要がある(Claude側からは安全機構により自動設定できない)。
