# SNS投稿下書き作成(Instagram / damage_mark_official)

村上さんの「文章を考える手間」を減らしつつ、**AIが書いたと分からない、村上さん本人の言葉づかいの投稿文**を作ることが最重要目的。下書きの自動投稿はまだ行わない(第1段階は下書き作成まで。投稿は村上さんが自分でInstagramアプリから行う)。

## 全体の処理フロー

### ステップ0: 文体ガイドの確認・ヒアリング(初回のみ、以後はスキップ)

1. 「文体サンプル」フォルダに `style_guide.md` があるか確認する。
2. なければ、村上さんに以下の観点を質問形式でヒアリングし、回答をもとに `style_guide.md` を作成して「文体サンプル」フォルダに保存する。一度に全部聞く必要はなく、2〜3個ずつ聞いてよい。
   - 普段の一人称(私/僕/自分の名前 等)
   - 文末の口調(です・ます調か、だ・である調か、カジュアルな口語か)
   - よく使う言い回し・口癖・絵文字の使い方(頻度・好んで使う絵文字)
   - 逆に「絶対に使わない」表現・NGワード(硬すぎる敬語、紋切り型のフレーズ等)
   - 投稿の長さの目安(短文中心か、しっかり語るタイプか)
   - ブランド・アカウントとしての世界観やコンセプト(damage_mark_officialとしてどんな雰囲気を出したいか)
   - ハッシュタグの使い方(付ける/付けない、よく使うタグ)
3. `style_guide.md` は箇条書きでよい。完璧を目指さず、まずは骨子を作る。

### ステップ1: 素材選定(重み付きランダム)

1. 「素材管理」スプレッドシートを読み込む。
2. 「SNS用画像」フォルダの中身と突き合わせ、スプレッドシートに未登録のファイルがあれば、使用回数0・登録日=今日として追記する。
3. 全素材の「使用回数」を見て、**使用回数が少ないものほど選ばれやすい重み付きランダム抽選**で1点を選ぶ(例: 重み = 1 / (使用回数 + 1) で乱数抽選。使用回数0のものが複数あればその中からランダム)。「毎回いちばん使用回数が少ないものを固定で選ぶ」のではなく、ランダム性を残すこと。
4. 選んだ素材ファイルを読み込み、写っている内容(料理・商品・現場の様子・人物・シーン等)を把握する。

### ステップ2: キャプション案の作成

1. `style_guide.md` の内容を必ず踏まえて、選んだ素材の内容に合ったキャプション案を1〜3パターン作成する。
2. 次のような紋切り型のAIっぽい表現は避ける: 「〜してみました!」「ぜひチェックしてみてください」「いかがでしたでしょうか」「〇〇な一日でした」等の定型オチ、機械的な絵文字の羅列、説明的すぎる文章。
3. `style_guide.md` にNGワードの指定があれば厳守する。
4. ハッシュタグは `style_guide.md` の方針に従う(方針が未定なら付けずに提案するだけにする)。

### ステップ3: 下書きの保存

1. 「下書き」フォルダに `年-月-日-下書き.md`(当日の日付、同日に複数回作成する場合は末尾に連番)としてキャプション案を保存する。
2. 「投稿履歴」スプレッドシートに1行追加する: 作成日 / 使用素材(ファイル名) / キャプション案 / 承認状況(「未確認」で初期化) / 投稿日(空欄) / 投稿URL(空欄) / メモ(空欄)。
3. 「素材管理」スプレッドシートの当該素材の使用回数を+1、最終使用日を今日の日付に更新する。

### ステップ4: 村上さんへの報告

作成したキャプション案と、使った素材、保存先(下書きファイルと投稿履歴の行)を簡潔に伝える。投稿は村上さんが内容を確認し、良ければ自分でInstagramアプリにコピーして投稿する(この段階では自動投稿は行わない)。

## 運用ルール

- 起動は村上さんの声かけ(「SNS投稿案を作って」等)による都度実行のみ。自動の定期実行は行わない。
- 投稿頻度は週1回想定、下書きは2日に1回程度のペースで声がかかる想定(下書きを複数ストックし、村上さんが選ぶ)。
- 生成した文章が「AIっぽい」と村上さんからフィードバックがあった場合は、`style_guide.md` を一緒に更新し、次回以降の精度を上げていく。
- 自動投稿(Instagram Graph API連携)は将来の拡張候補だが、Meta側のビジネスアカウント化・アプリ審査等が必要なため今回のスキルには含めない。Instagramアプリの「下書き」機能への直接書き込みは公開APIが提供されておらず不可。
